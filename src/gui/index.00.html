初期セットアップ

Sqlite Fleetを使い始める前に、DB検出、許可ルート、マイグレーションSQLの場所を確認します。

導入手順

  1. 設定ファイルを配置し、Sqlite Fleetが触ってよいディレクトリを許可ルートに登録します。
  2. DB discoveryでDBの検出方法を選び、保存前にPreview discoveryで検出結果を確認します。
  3. Migration dirに信頼済みのSQLファイルを置き、マイグレーション管理で読み込み状態を確認します。
  4. Dry runで対象DBと適用予定を確認してから、マイグレーション適用へ進みます。

開始前チェック

現在読み込まれている設定と状態から自動判定しています。手動チェックではありません。

ヘルプ

            
詳細を読みたい時のリファレンスです。日常操作の要点は各項目のツールチップにも分散しています。

          

        

        

          

            
基本の考え方

            
    
              
  • マイグレーションファイルは migrations.dir の固定ディレクトリに置きます。
    • 
              
  • [migration_groups] はファイル名リストでグループを管理します。未設定時は全マイグレーションが main に入ります。
    • 
              
  • [database_migration_groups] はDBごとに対象マイグレーショングループを指定します。未指定DBは main を使います。
    • 
              
  • [db_groups] はカナリアなど、操作対象DBのまとまりを作るためのDBグループです。標準の all は全DBです。
    • 
            

          

          

            
画面の見方

            
    
              
  • DBではDBごとの適用済み件数、未適用マイグレーション、不整合を確認します。
    • 
              
  • マイグレーションでは読み込まれているマイグレーションファイルとchecksumを確認します。
    • 
              
  • マイグレーショングループではmainから分岐した各グループのマイグレーションをチェックボックスで編集できます。
    • 
            

          

          

            
操作

            
    
              
  • 状態を検査はDB状態、checksum、不明な適用履歴を検査します。
    • 
              
  • Dry runは対象DBの未適用マイグレーションを確認します。DBは変更しません。
    • 
              
  • 適用は対象DBの未適用マイグレーションをversion順に適用します。選択中の1ファイルだけを飛ばして適用する操作ではありません。
    • 
              
  • BackupはSQLite backup APIでDBの一貫したコピーを backup.dir に作成します。
    • 
            

          

          

            
SQL Console

            
    
              
  • SQLを選択DBに対してdry-runまたは適用できます。マイグレーション履歴には登録されません。
    • 
              
  • SQL applyはatomic transactionで実行します。途中で失敗した場合はrollbackします。
    • 
              
  • ATTACH / DETACH はGUI SQLでは拒否されます。
    • 
              
  • VACUUM、PRAGMA journal_mode は単独SQLとしてだけ適用できます。VACUUM INTO はGUI SQLでは拒否されます。
    • 
            

          

          

            
安全設定と監査ログ

            
    
              
  • [gui]: GUI操作権限を制限します。デフォルトでは読み取り系の check だけを許可します。
    • 
              
  • DBを書き換える操作、backup、SQL apply、migration編集を有効にする権限: allow_migrate、allow_backup、allow_sql_apply、allow_migration_edit
    • 
              
  • allow_restore: 現在のGUIにはrestore実行画面はありません。復元はCLIで実行してください: sqlite-fleet restore
    • 
              
  • audit.path を設定すると、GUIのmigrate、backup、SQL applyもJSONLへ記録されます。
    • 
              
  • 監査ログを書けない場合、GUI APIは成功扱いにしません。
